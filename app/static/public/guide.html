1. 系统构成与角色1. System & roles

系统由三部分组成：手机 App（工人现场拍摄上传）、管理后台（经理审核、管理、出报告）、服务器（云端工作区或您自己的 NAS/服务器）。每条上传记录自动附带项目、工号、GPS 和拍摄时间，构成可追溯的工地影像证据。 Three parts: the mobile app (crews shoot and upload on site), the manager portal (review, admin, reports), and the server (a hosted workspace or your own NAS/server). Every upload carries project, employee, GPS, and capture time — a traceable evidence trail.

2. 安装与首次启动2. Install & first run

使用我们托管的云端工作区可跳过本节（从申请开通开始）。本节针对自建部署。 Skip this section if you use our hosted workspace (start at Request access). This is for self-hosting.

2.1 TerraMaster NAS（TOS 7 应用中心）2.1 TerraMaster NAS (TOS 7 App Center)

  1. 在应用中心搜索 KK Field Logger，点击安装，选择存放数据的存储卷。Search KK Field Logger in the App Center, install, pick the storage volume for its data.
  2. 等待容器启动（首次启动要初始化数据库，约 1–3 分钟）。Wait for the containers to start (first boot initializes the database, 1–3 minutes).
  3. 打开应用（默认端口 8090），进入初始化向导：填公司名、管理员邮箱和密码，一步建好工作区。Open the app (default port 8090) and complete the setup wizard: company name, admin email, password — one step.
配置要求：x86 机型开箱即用；ARM 机型需要 2GB 及以上内存（1GB 内存机型不支持）。数据存放在所选卷的 DockerAppData/kkfieldlogger/ 下：media（照片视频）、database、backups、logs、config。 Requirements: x86 models work out of the box; ARM models need 2GB+ RAM (1GB models are not supported). Data lives under DockerAppData/kkfieldlogger/ on the chosen volume: media, database, backups, logs, config.

2.2 任何支持 Docker 的设备2.2 Any Docker-capable device

同一套镜像适用于其他 NAS、软路由或普通服务器。到 GitHub 仓库取 deploy/nas/docker-compose.yml，把 /Volume*/DockerAppData 换成本机路径后： The same images run on other NASes, soft routers, or plain servers. Grab deploy/nas/docker-compose.yml from the GitHub repo, replace /Volume*/DockerAppData with local paths, then: 

docker compose up -d
# 首次启动自动执行全部数据库迁移 / first boot runs all migrations
# 然后访问 http://<主机>:8090 完成向导 / then visit http://<host>:8090

镜像为 kkkdata/kkfieldlogger，同一 tag 同时支持 amd64 与 arm64。标准版即够用；-full 变体额外内置语音转写与视频关键帧提取（体积更大，建议 x86 使用）。 Images: kkkdata/kkfieldlogger; each tag serves both amd64 and arm64. The standard variant is enough for most; the -full variant adds in-image voice transcription and video keyframes (bigger; best on x86).

3. 快速上手三步3. Quick start

  1. 建项目：后台「项目」页新建项目（工地）。Create a project on the Projects page (one per jobsite).
  2. 加员工、发密钥：「员工」页添加工人并分配项目；系统为每人生成一个上传密钥，把密钥发给工人即可，无需为工人开邮箱账号。Add employees, issue keys: add workers on the Employees page and assign projects; each gets an upload key. Hand the key to the worker — no email account needed.
  3. 工人装 App 开拍：工人在手机装好 App、录入密钥，到工地即拍即传；照片几秒后出现在后台。Workers install the app, enter their key, and shoot; uploads appear in the portal within seconds.

4. 工人端：手机 App4. Field: the mobile app

  • 登录：首次打开输入服务器地址（NAS 部署时）和上传密钥即可，之后保持登录。Sign in: on first launch enter the server address (for NAS installs) and the upload key; it stays signed in.
  • 拍摄：支持照片、视频、语音备注、票据。选定项目后拍摄，记录自动带上项目、工号、GPS 与时间。Capture: photos, video, voice notes, receipts. Pick the project and shoot; each record carries project, employee, GPS, and time.
  • 离线队列：没信号照拍不误——记录先存本机，网络恢复后自动补传，重复上传自动去重（同一张照片不会传两份）。Offline queue: no signal, no problem — records queue locally and upload when coverage returns; duplicate uploads are deduplicated automatically.
  • 报错提示：所有错误均为结构化提示，支持英文、中文、西班牙语，并注明是否可重试。Errors are structured and localized (EN/中文/Español) and say whether a retry will help.
工人被误分到错误项目也不丢数据：服务器会把照片挂到可用项目并记录原始项目信息，经理后续可改。 Wrong project assignment never loses data: the server files the photo under an available project and records the original intent for managers to fix later.

5. 经理后台逐页说明5. Manager portal, page by page

浏览器访问 /login 登录。界面语言可在「语言」菜单切换（中文/英文）。 Sign in at /login. Interface language (中文/English) switches from the Language menu.

5.1 今日工作台（登录首页）5.1 Today workbench (landing page)

回答一个问题：今天有什么需要我处理？集中显示今日上传动态、异常告警（任务队列积压、处理失败）、待办入口。想用旧版总览，点「经典视图」。 It answers one question: what needs my attention today? Today's upload activity, alerts (queue backlog, failed processing), and shortcuts. The classic dashboard is one click away.

5.2 照片库5.2 Photo library

  • 筛选：按项目、员工、日期、审核状态过滤；支持网格（图库）和地图视图（按 GPS 落点看照片分布）。Filter by project, employee, date, review status; grid (gallery) and a map view plotting photos by GPS.
  • 单张操作：批注、评论、审批（通过/驳回）、设为客户可见、重新触发 AI 分析。Per-photo: annotate, comment, approve/reject, mark client-visible, re-run AI analysis.
  • 批量操作：勾选多张后可批量批注、批量审核、批量删除。Bulk actions: select many, then bulk-annotate, bulk-review, or bulk-delete.
  • 回收站：删除先进回收站，可随时恢复；NAS 版 30 天后自动清理，也可手动清空。彻底销毁不可恢复。Recycle bin: deletes go to the bin and can be restored; the NAS edition auto-purges after 30 days, or empty it manually. Destroy is permanent.
  • 客户可见性：客户账号默认看不到任何照片，只有明确标记的才会出现——先审后见。Client visibility: client accounts see nothing until a photo is explicitly marked visible — curation first.

5.3 项目5.3 Projects

建项目、改名、看单项目照片汇总；「导出」可把项目资料打包带走。 Create and edit projects, see per-project photo rollups; Export packs a project's records for hand-off.

5.4 员工与用户5.4 Employees & users

  • 员工（工人）：添加、分配项目、停用/启用；上传密钥可重新生成（旧密钥立即失效，适用于手机丢失或人员离场）。Employees (workers): add, assign projects, activate/deactivate; upload keys can be regenerated (the old key dies instantly — for lost phones or departures).
  • 用户（后台账号）：管理员可调整角色、重置密码、停用账号。Users (portal accounts): admins change roles, reset passwords, deactivate.

5.5 报告5.5 Reports

按项目和日期范围生成 PDF 报告，可下载存档；还有进度对比视图（同一项目不同时间段的对照）。生成失败可一键重试。 Generate PDF reports by project and date range, download for filing; a progress-compare view sets two periods of the same project side by side. Failed generations retry with one click.

5.6 IP 摄像头5.6 IP cameras

可接入工地固定 IP 摄像头做定时抓拍，支持连通性测试与健康状态总览，也可批量添加。 Fixed jobsite IP cameras can be added (individually or in bulk) for scheduled captures, with connectivity tests and a health summary.

5.7 审计日志与系统健康5.7 Audit log & system health

每一次审批、删除、密钥变更等敏感操作都记录在审计日志里，谁在何时做了什么，随时可查。「系统健康」页显示队列、存储和后台任务状态。 Every approval, deletion, and key change lands in the audit log — who did what, when. The System Health page shows queue, storage, and worker status.

5.8 设置与个人资料5.8 Settings & profile

「设置」管工作区级选项；「个人资料」改自己的密码。 Settings holds workspace-level options; Profile is where you change your own password.

6. AI 助手6. AI assist

  • AI 后端：在「AI 后端」页接入您自己的视觉模型服务（如本地 Ollama 或云端 API），保存前可先「测试连接」。不配置 AI 系统也完全可用。AI backends: connect your own vision-model service (local Ollama, or a cloud API) on the AI Backends page; test the connection before saving. The system is fully usable without AI.
  • AI 中心：查看分析任务队列与结果，失败任务可重试；分析结果（摘要、标签）可采纳进正式记录，采纳错了可回滚。AI Center: watch the analysis queue, retry failures; results (summaries, tags) are promoted into the record explicitly and can be rolled back.
  • 原则：未经验证的 AI 输出不会自动进入报告或客户可见内容——AI 只做助手，不做裁判。Principle: unverified AI output never flows into reports or client-visible content on its own — AI assists, it doesn't decide.

7. 备份、保留与升级7. Backups, retention & upgrades

7.1 备份7.1 Backups

每次升级如包含数据库结构变更，系统会先自动做一次数据库备份再执行迁移，保留最近 5 份，存放在数据卷的 backups/ 目录。建议另外定期把整个 DockerAppData/kkfieldlogger/ 目录（含 media 与 database）纳入您的 NAS 备份计划。 Whenever an upgrade carries database schema changes, the system takes an automatic database backup first, keeping the latest five in the data volume's backups/ directory. Additionally, include the whole DockerAppData/kkfieldlogger/ tree (with media and database) in your NAS backup plan.

7.2 自动保留策略（磁盘保护）7.2 Retention (disk protection)

数据Data策略Policy
回收站照片Recycled photos30 天后自动清理（NAS 版）Auto-purged after 30 days (NAS edition)
被新结果取代的 AI 分析日志Superseded AI analysis logs保留 180 天Kept 180 days
审计日志Audit logs保留 365 天Kept 365 days
已完成的后台任务记录Completed job records保留 30 天Kept 30 days

照片和视频本体永不自动删除——只有回收站里的会过期。 Original photos and videos are never auto-deleted — only items already in the recycle bin expire.

7.3 升级7.3 Upgrades

应用中心内点击更新即可；自建 Docker 部署执行 docker compose pull && docker compose up -d。数据库迁移在启动时自动完成（升级前自动备份见 7.1）。 Click update in the App Center; plain Docker installs run docker compose pull && docker compose up -d. Migrations apply automatically on boot (with the pre-upgrade backup from 7.1).
